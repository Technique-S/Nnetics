# Nnetics demo design audit

Baseline `7657c9f` on `feature/nnetics-v3`. Implementation is isolated on `codex/nnetics-final-design`. The sibling `feature/task-dashboard-demo` checkout has uncommitted component, route and test files. The V3 baseline contains the newer six-destination navigation, contractor lifecycle guards and prepare/confirm simulation.

## Inventory and evidence

Next's production route inventory contains three user-facing routes, plus the not-found and runtime error boundaries. The owner dashboard uses query mode and hash destinations. Each hash and the overlays beneath it are included here. The standalone contractor demo and the private portal are separate entry points. The payment confirmation uses the existing guarded inline review. Contractor and vault destructive actions use native browser confirmation.

The 69 [before captures](design-review/final-design/before/) use local production Chromium at 1440px and 375px. The screenshot script uses fresh browser contexts and local simulated records. It masks the private invite field and intercepts requests only to exhibit loading, retry and provider failure. [Capture results](design-review/final-design/before/results.json)

P0 indicates an obstructed interaction. P1 indicates a serious hierarchy, navigation or responsive issue. P2 indicates an inconsistent component or feedback. P3 indicates refinement.

## Baseline findings and limits

- Browser inspection confirmed the Overview overlap, the clipped More control and the split visual identity. The baseline More overlay also stayed open after Escape. The original light primary pair, white over `#84CC16`, measures approximately 1.98:1. The workspace body also uses a gray outer frame literal that bypasses the theme check.
- Live organization selection, provisioning, wallet signing, transaction review and session-recovery states were inventoried from source and the existing browser fixtures. The design capture does not use a real wallet, authorize a privileged action or execute a live transfer.
- Assistant provider failures can be shown with a browser fixture. Provider-backed responses require server credentials. A missing provider is a real operational limit.
- The webpack development server produced an existing runtime-reference URL error. The default Turbopack production baseline built and served successfully. Browser evidence uses the default bundler.

## Reference applications

- Apple motion and Framer feedback informed short, reversible overlay and control transitions with a reduced-motion path. [Apple Motion](https://developer.apple.com/design/human-interface-guidelines/motion) · [Framer hover and press](https://www.framer.com/academy/lessons/framer-animations-hover-and-press-effects)
- Duolingo informed one primary task per setup step and persistent completion. [Duolingo home-screen redesign](https://blog.duolingo.com/new-duolingo-home-screen-design/)
- Linear and Notion informed stable navigation, compact records and views over the same data. [Linear design refresh](https://linear.app/now/behind-the-latest-design-refresh) · [Notion views and filters](https://www.notion.com/help/views-filters-and-sorts)
- Pentagram, Muji, Aesop and Stripe informed typography, quiet forms, restrained presentation and a demo-first entry. [Pentagram typefaces](https://www.pentagram.com/typefaces) · [Muji design](https://www.muji.eu/pages/muji-stories/the-art-of-simple-design.html) · [Aesop story](https://www.aesop.com/our-story.html) · [Stripe](https://stripe.com/)
- Airbnb informed combinable search, filters and reset behavior. WCAG 2.2 informed contrast, focus, input and mobile checks. [Airbnb search filters](https://www.airbnb.com/help/article/252) · [WCAG 2.2](https://www.w3.org/TR/WCAG22/)
